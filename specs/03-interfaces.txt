freegal TUI — INTERFACES REFERENCE
================================================================================

WHAT THIS FILE IS
  The complete catalogue of freegal's TUI surfaces, each with its INTENTION
  (why the interface exists, what the user is meant to accomplish there, and
  which web-parity decisions shaped it), its keys, its API backing, and a
  captured panel.

HOW TO USE IT
  - "Interface refreshes" start here: pick a surface, read its intention, then
    change the renderer + this file in the same commit.
  - Panels are generated from the insta snapshot tests (src/ui/tests.rs). To
    refresh panels after a UI change: INSTA_UPDATE=always cargo test --release
    snapshot_  →  review each *.snap diff per file  →  delete stale *.snap.new
    (see AGENTS.md etiquette)  →  re-run this generator.
  - Intent lines are the non-negotiable part: if code and this file disagree,
    one of them is wrong.

GLOBAL DESIGN PRINCIPLES
  - One screen enum (Login/Resume/Home), five TABS: 1 Home · 2 My Music ·
    3 Queue · 4 History · 5 Downloads. Tabs are view filters, not screens —
    the Screen stays Home once signed in.
  - Tab bar shows names only (Home │ My Music │ …). With five tabs the old
    "[n] Name" pills no longer fit 80 cols beside the status chip, so the
    digits moved to the hint bar and live on as keys (1-5 / s m q d h).
  - Esc ALWAYS pops exactly one drill level and never crosses tabs.
  - Feeds are human-paced sequential GETs, 30-minute disk cache (cache.json);
    R = refetch (fresh), bypassing cache.
  - Freegal rc-as-empty map (server uses codes instead of messages for empty
    user state): 46 no songs · 115 no playlists · 174 no downloaded ids ·
    247 nothing streamed · 640 unavailable-for-library. All render as empty
    states, never errors. 235/233 on bare genres = success-alternates
    (data still parses).
  - TestBackend snapshots record SYMBOLS only (colors invisible); the genre
    dots ● and chips get their colors from chrome::genre_dot(title) — a
    deterministic 12-hue palette hash.

01 · LOGIN WIZARD  (4 steps)
================================================================================
intention : Get a patron authenticated with zero terminal knowledge: subdomain → library confirm → library card → PIN, with a manual libraryId fallback modal when a subdomain resolves to several libraries. Everything is invisible afterwards (silent re-auth restores the exact prior screen).
keys      : type · Enter next · Esc/back back a step · credentials land in ~/.config/freegal/creds.toml (0600)
api       : library resolve (subdomain), login with card+PIN, bootstrap pairing token
empty     : errors render inline in the wizard card
notes     : wizard is the only true Screen other than Home; re-auth is invisible

02 · HOME TAB — root dashboard
================================================================================
intention : Web-parity of Freegal's home page (Nov 2026): the library's editorial dashboard as one keyboard-navigable column. Five quick links (Discover Artists / Now Trending / New Arrivals / Discover Albums / Explore Playlists / Explore Genres) mirror the web's image-card quick links; below, nine sections in the web's own order with clickable heading rows, 4 items each. Sidebar = the Library's Playlists (library-scoped, same for every patron).
keys      : ↑↓ jk / g G move · ←→ focus sidebar · Enter open (heading = full drill, song = play) · a/A queue · y download · / or s search · R refetch feeds · 1-5 tabs
api       : one client call home_feed(HomeFeed,limit,fresh) over slugs: songs/featured, albums/recommended (More of what you'd like — ALBUMS on the real site), playlists/library-playlists, user/songs/recently-played, playlists/recommended, playlists/featured, artists/featured, albums/new, playlists/top (+songs/top, albums/featured for quick-link drills)
empty     : sections hide themselves until Done; failed section names itself in the status row with 'Error: <title>: <e> — R to retry'
notes     : recently-played is user state (server-side per patron); quick-link drills fetch 50 rows (DRILL_LIMIT)

================================================================================
intention : Web parity of Freegal's My-Music composite page, i.e. the patron's own server-side data: My Playlists, Downloaded Songs, Favorites, Wishlist, in the web's order, headings clickable like Home, 4 items each. When the server answers with the empty codes (46/115) the section still renders its heading above the SITE'S OWN empty-state sentence, so an empty patron looks intentionally empty, never broken. This patron is empty server-side today — which is exactly what the design anticipates.
keys      : ↑↓ jk · g G · Enter open (heading = drill) · playlist rows jump to Home and open the playlist · Enter on songs plays (rest queued) · a queue · y download · R refetch · 1-5 tabs
api       : user/playlists (rc 115 = none) · user/downloaded/songs (rc 46 = none) · wishlist/songs?contentType=favorite (46) · wishlist/songs?contentType=wishlist (46)
empty     : per-section web phrasing: 'Your created playlists will appear here.' · 'Your downloaded songs will appear here.' · 'Your Favorite Songs, Playlists, Albums will appear here.' · 'Your Wishlist Songs will appear here.'
notes     : favorites show SONGS only (web also rails favorite albums/playlists — omitted; wishlist/books rc 640 = audiobooks unavailable, section omitted)
